# 可验证证据要求

## 证据规则

可接受证据必须能由 PR 审查者复现或直接在材料中检查：带结果的测试名称/命令、扫描报告、关键 HTTP 请求/响应、diff 中可见的服务端控制，以及已核验的风险接受记录。没有材料时写“未提供”；不要猜测、补写或把计划执行的检查算作通过。

风险等级必须记录影响范围、可利用性、暴露范围和可达性的依据。扫描告警时，证据应包含可获得的 CVSS、EPSS、KEV 和运行时可达性信息；CVSS 标签本身不是最终结论。已知被利用、互联网可访问、低权限可利用、运行时可达或影响账户/租户/支付/敏感数据的任一事实，都会提高处置优先级。

没有实际 PR diff 时，不能把摘要、作者说明或模型结论当作 diff 证据。必须按“涉及”或“无法判断”的敏感面索取对应证据；不得因仅 CI、配置或依赖改动而要求 401/403、用户 A/B、租户归属或失效 Token 等接口鉴权证据。中心模板的标准 `pull_request` 入口本身不构成风险项或技术债。涉及的敏感面缺少对应证据时必须 `BLOCK`。

## 按敏感面检查

| 敏感面 | 检查重点 | 最低可验证证据 |
| --- | --- | --- |
| 接口、认证 | 私有端点、登录、Token、会话、失效/撤销 | 未登录请求得到 401/403；失效 Token 不能继续使用。 |
| 鉴权、权限、数据 | 服务端角色校验、对象归属、租户边界、管理员操作 | 普通用户不能访问管理员资源；用户 A 不能读取或修改用户 B 数据；租户/资源归属来自服务端认证上下文，而非可伪造的客户端参数。 |
| 支付、后台管理、用户数据 | 金额/状态变更、管理 API、批量导出、个人数据 | 权限拒绝、资源归属与关键状态变更的测试或请求/响应；证据不足时 `BLOCK` 并人工复核。 |
| 文件 | 类型、大小、内容校验、路径遍历、下载授权、对象存储权限 | 非法类型/路径被拒绝；上传/下载需认证与归属校验；文件不以可执行方式被直接处理。 |
| 输入处理 | SQL/命令/模板注入、SSRF、反序列化、外部回调 | 参数化查询或等效安全 API 的 diff 证据；危险输入被拒绝的测试；回调签名/来源校验。 |
| 敏感信息、日志 | 密钥、Token、私钥、`.env`、个人数据、调试日志 | 密钥扫描通过；日志/错误响应不含敏感值；疑似泄露一律作为 P0 处理，必要时吊销/轮换。 |
| 配置、部署 | CORS、Cookie、安全头、调试模式、容器、IaC、网络暴露 | 变更后的配置 diff；相关配置/镜像/IaC 扫描结果；不安全默认值的修复说明。 |
| 依赖 | 新增或升级依赖、锁文件、漏洞公告 | 依赖漏洞扫描结果，包括 CVSS、EPSS、KEV 和运行时可达性；已知被利用或高 EPSS 且生产可达、影响核心数据时升级 P0。仅开发依赖或代码不可达时，提供范围/可达性证据后可列 P1/P2。 |
| CI | 扫描跳过、密钥权限、第三方 Action、部署条件 | 工作流 diff；密钥、静态、依赖扫描的结果；必要时镜像/IaC 扫描结果。 |

## 外部 API、批处理与错误语义

对外部 API、批处理或同步逻辑变更，要求测试或请求/响应证据覆盖：

- 边界批次，例如单批上限为 50 时的 50 条和 51 条；
- 部分批次失败：成功批次、失败批次和汇总如何呈现；
- 全部批次失败：是否抛错、返回明确失败状态或触发告警；
- 调用方状态映射：API/网络失败不得被展示为“未找到”“未匹配”或其他正常业务状态；
- 重试、超时、幂等和失败后确认/写入行为（适用时）。

审查 `raise` 改为 `{}`、`[]`、`None`、`False` 或空字符串等降级返回值。记录变更前后调用方如何区分成功、业务空结果和系统失败；若错误会影响权限、核心数据、资金、工资、考勤结算或审计可见性，升级为 P0 并 `BLOCK`。

## 日志可观测性

若失败详情写入 `logger.extra`，提供 formatter 配置、日志样例或日志平台查询结果，证明 `batch_no`、错误码和安全的错误信息可见、可检索。没有该证据时，将日志诊断不足列为 P2 技术债，并建议将不含手机号、Token、Cookie 等敏感值的关键信息写入日志正文，或配置结构化日志输出。

## 最低 CI 门禁

要求 CI 至少提供以下机器证据：

- 密钥扫描；
- 静态安全扫描；
- 依赖漏洞扫描；
- Docker 或 IaC 变更时的镜像和配置扫描。

静态扫描只能识别部分模式问题，无法可靠证明业务越权安全。因此，涉及接口或数据访问时，必须同时提供授权回归测试和必要的人工安全复核。扫描未提供、失败或被跳过时，必须在“已验证证据”中逐项写出实际状态。

## 人工安全复核触发条件

以下任一情况要求人工安全复核，并在复核完成前保持 `BLOCK`：

- 登录、权限、支付、用户数据、后台管理、文件上传或外部回调发生变更，但授权/边界测试证据不足；
- 发现或怀疑 P0；
- 业务规则决定访问边界，自动化扫描无法验证；
- 攻击路径、影响范围或补救措施无法从 PR 材料可靠确定。

人工复核是补充证据，不能把未验证的实现假设为安全。
