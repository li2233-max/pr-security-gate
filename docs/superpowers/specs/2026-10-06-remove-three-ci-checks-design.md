# Remove three PR checks from pr-security-gate and weixin

Date: 2026-10-06

Status: design approved in conversation; this written specification awaits user review. No runtime workflow or test files have been changed by this document.

## Goal and accepted trade-off

The user wants the payment/refund test, authorization test, and Semgrep scan checks removed entirely from both the central independent verifier and the weixin Quality gates. The two test jobs must not be skipped or converted to non-blocking jobs. The 16 test source files those weixin jobs cover must also be deleted. Payment, refund, authorization, and other application implementation code stays.

This deliberately removes automated regression coverage for payment, refund, authorization, and other behavior represented by those test files. It also removes Semgrep static scanning. A passing remaining gate must never be reported as evidence that the removed tests or scan ran.

## Current constraints

- The central verifier profile, workflow, runner, manifest, and tests currently require six independent checks. Removing only the workflow jobs would make the verifier or manifest invalid.
- The weixin architecture contract on protected main requires payment-refund-tests and authorization-tests for two critical paths. The architecture gate evaluates the protected base contract, so PR #4 cannot waive those requirements by editing its own contract.
- The current contract parser requires each criticalPaths.requiredChecks array to be non-empty. The two obsolete critical-path entries must be removed from the weixin baseline contract, not changed to empty arrays. Other architecture rules remain.
- The central verifier is approved by an immutable commit SHA. A changed verifier must be merged and then approved at its final SHA before PR #4 can pin it.
- GitHub Ruleset required-check settings are outside these Git changes. If they name removed checks, the repository owner must update them before merge. The agent must verify rather than assume their state.

## Rollout and failure behavior

1. Implement and test the central three-check verifier in a central PR; the user reviews and merges it.
2. Approve V in a separate central registry change; the user reviews and merges it. The resulting approval commit is G. PR #4 must use V for the independent workflow and G for AI review, not a branch name or mutable tag.
3. Merge the weixin contract-only baseline PR into main after its own checks and review pass.
4. Update PR #4 with the three Quality job removals, the 16 test deletions, the new approved verifier pin, and current main. Rerun all remaining checks.
5. Inspect the actual main Ruleset. Remove only required-check entries corresponding to deleted jobs, if present. This setting change requires repository-owner action; do not silently relax other requirements.

Old failed workflow runs remain historical GitHub records. They cannot be rewritten into PASS; a new candidate SHA must be evaluated using the new approved verifier. If any retained check, AI security review, architecture rule, or Ruleset condition fails, PR #4 remains blocked and the actual reason must be reported. This design does not promise that PR #4 will pass.

## Alternatives considered

- Keep the jobs but use continue-on-error or always-skipped conditions: rejected because the user requested complete removal and these states can mislead reviewers.
- Change the contract and Quality workflow together inside PR #4: rejected because the protected base contract still demands the two checks and the modified Quality workflow cannot independently approve its own contract change.
- Remove the central checks but leave the 16 weixin test files: rejected by the user's explicit request to delete all files covered by the two test jobs.

## Verification and acceptance

- Central unit and workflow tests pass with an exact three-check profile and manifest. Negative tests still reject missing, skipped, stale, or forged retained checks and unapproved verifier SHAs.
- Search confirms the three deleted check IDs are absent from active central workflow/profile/manifest requirements and absent from active weixin Quality jobs and architecture critical-path requirements. Historical prose or test fixtures may mention them only as documented old behavior.
- The 16 listed test files are absent from PR #4. Remaining weixin production-hardening, dependency, secret, and architecture jobs run on the new candidate SHA; do not claim removed test coverage.
- The contract-only baseline PR runs architecture-owner-approval from an unchanged base Quality workflow. The real GitHub PR #4 is checked after main and the verifier approval are current. Ruleset required-check names are inspected and reconciled.
- No force push, direct main commit, status fabrication, gate bypass, or automatic merge is part of this design.
